## 1. Co się zmieniło (w jednym zdaniu)

Per-katalogowa kalibracja (`<dir>/calibration.json`, nieosiągalna z UI) została
**zastąpiona globalną, nazwaną biblioteką skal**: użytkownik wgrywa zdjęcie
wzorca (linijki), mierzy odcinek 2 kliknięciami, podaje wartość rzeczywistą i
nazwę, a skala trafia do biblioteki, z której wybiera ją z menu w lewym panelu.
Przy cropie każdy wycinek dostaje pasek skali zgodny z aktywną skalą.

## 2. Model danych

- **Skala = globalny preset**, niezależny od katalogu/obrazu. Wybierany w
  sidebarze; ostatni wybór zapamiętany w `localStorage` (`turbot.activeScaleSlug`)
  → odtwarzany przy kolejnym uruchomieniu.
- **Przechowywanie:** katalog `SCALES_DIR` (domyślnie `DATA_ROOT/_scales`,
  konfigurowalny env-em `SCALES_DIR`). Trzymany **pod DATA_ROOT**, żeby endpoint
  `/api/image/preview` mógł serwować wgrane wzorce (potrzebny `X-Scale` do
  przeliczenia pomiaru preview→oryginał).
- **Pliki:** jeden preset = `<slug>.json` + kopia zdjęcia wzorca `<uuid>.<ext>`.
  Nazwa skali jest kluczem (slug) — zapis pod istniejącą nazwą = edycja
  (nadpisanie), stara kopia zdjęcia jest wtedy sprzątana.
- **Kanoniczna wartość:** `um_per_px` w rozdzielczości **oryginału**. Skala jest
  poprawna tylko dla zdjęć przy **tym samym powiększeniu** co wzorzec — pole
  `magnification` + nazwa pomagają to utrzymać (powiększenie widać w dropdownie).

### Format `<slug>.json`
```json
{
  "name": "microscope_4x",
  "slug": "microscope_4x",
  "um_per_px": 50.0,
  "length_real": 2.0,
  "unit": "cm",
  "magnification": "4x",
  "source_filename": "_scales/24a6fa...0b.jpg",
  "p1": [100.0, 100.0],
  "p2": [300.0, 100.0],
  "dist_preview_px": 200.0,
  "created_at": "2026-06-19T12:02:10+00:00"
}
```

### Wzór przeliczenia (single source of truth = backend)
```
dist_preview_px = hypot(p2 - p1)                       # przestrzeń preview wzorca
length_um       = length_real * {cm:10000, mm:1000, um:1}[unit]
um_per_px       = length_um * scale / dist_preview_px  # scale = X-Scale wzorca (preview→original)
```
Weryfikacja: 2 cm, 200 px preview, scale 0.5 → `20000 * 0.5 / 200 = 50.0 μm/px` ✅

## 3a. Zoom w oknie pomiaru (dodane 2026-06-19, po pierwszym wdrożeniu)

**Powód:** przy dużym zdjęciu i małej skali trudno precyzyjnie kliknąć 2 punkty.

**UI:** pasek nad canvasem modala — `−` (pomniejsz), etykieta `%`, `＋` (powiększ),
`Fit` (dopasuj do okna), hint „scroll to pan". Pojawia się po wgraniu wzorca.

**Działanie:**
- `displayScale` = liczba CSS px na 1 px obrazu. `＋`/`−` mnoży o ×1.25 / ×0.8
  (zakres 0.05–8), `Fit` liczy `clientWidth/img.width` (max 100%).
- Zoom steruje **tylko szerokością wyświetlania** canvasu (`$canvas.style.width`);
  rozdzielczość wewnętrzna (atrybuty `width/height` = rozmiar preview) bez zmian.
- `.scale-canvas-wrap` ma `overflow:auto` (scroll w obu osiach) + `text-align:left`
  (pewny dostęp do lewej krawędzi przy panowaniu).

**Poprawność pomiaru:** `onCanvasClick` przelicza klik przez
`canvas.width / rect.width` (rect = rozmiar wyświetlany), więc współrzędne punktów
i wyliczone `um_per_px` są **identyczne przy dowolnym powiększeniu**.

**Weryfikacja:** `node --check app.js` ✅; serwowane `#scale-zoom-{in,out,fit,label}`
✅; reguły `.scale-zoombar` w CSS ✅. Zmiana czysto frontendowa (statyki bez cache
— wystarczy F5).

## 3b. Wybór katalogów wejścia/wyjścia — wiele rootów (dodane 2026-06-19)

**Powód:** użytkownik musi nawigować po drzewie katalogów (wejście i wyjście), nie
być zamkniętym w jednym `DATA_ROOT`.

**Model:** allow-lista **nazwanych rootów** (`config.ALLOWED_ROOTS`). Ścieżki w API
mają format `<RootName>/pod/katalog`; pusty `` = **wirtualny top** listujący roots.
Każdy root to bezpieczna „wyspa" (guard `is_relative_to` pod tym rootem); absolutne
ścieżki serwera nie wyciekają do klienta. Działa identycznie lokalnie i zdalnie —
zawsze przegląda dysk **serwera** (lokalnie = komputer użytkownika).

> Decyzje użytkownika: scenariusz **Oba** (lokalnie i zdalnie), **allow-lista**
> katalogów, **tylko roots serwera** (bez uploadu z laptopa klienta).

**Konfiguracja:** env `ALLOWED_ROOTS="Nazwa=ścieżka;Nazwa2=ścieżka2"`. Domyślnie
`{data: DATA_ROOT}` (zgodność wstecz). Aktualny setup: `Documents=C:\Users\kswitek\Documents`.

**Zmiany w plikach:**
- `web/config.py` — `_parse_allowed_roots()` + `ALLOWED_ROOTS`; wpis w `describe()`.
- `web/services/fs_browser.py` — przepisane `safe_resolve`/`to_rel`/`list_dir` na
  model root-prefixed; wirtualny top (lista rootów); zarezerwowany root `_scales`
  → `SCALES_DIR` (rozwiązywalny, ukryty w listingu). **Sygnatury bez zmian**, więc
  routery/serwisy (`fs`, `image`, `detect`, `crop`, `scales`, `image_service`)
  **nie wymagały zmian**.
- `web/static/app.js` — `FileBrowser`: na wirtualnym topie wyłączone „📁 New folder"
  i „save here"; breadcrumb roota = „⌂ roots". Reszta renderu generyczna (działa bez zmian).

**Weryfikacja (API):**
- top → `{"dirs":[{"name":"Documents"}]}` ✅; wejście w `Documents` → parent `""` ✅.
- nawigacja w głąb do `…/test_images` → 10 obrazów, parent łańcuchuje ✅.
- guard: `Documents/../..` → **403** ✅; root spoza listy `C:/Windows` → **403** ✅.
- preview obrazu po ścieżce root → 200 + `X-Scale` ✅.
- scales upload → `_scales/…` + preview 200 ✅; crop do `Documents/…/_crop_test`
  → 2 PNG z paskiem skali ✅.

## 4. API

| Metoda / ścieżka | Opis | Body / params |
|------------------|------|---------------|
| `GET /api/scales` | Lista presetów (sort po nazwie). | — |
| `POST /api/scales/upload` | Wgranie zdjęcia wzorca (multipart). | `file` → zwraca `{path}` (`_scales/<plik>`, zarezerwowany root) |
| `POST /api/scales` | Utworzenie/edycja presetu. | `{name, magnification, p1, p2, length_real, unit, scale, source_filename}` → `ScaleResponse` |
| `DELETE /api/scales/{slug}` | Usuń preset + kopię zdjęcia. | → `{deleted:true}` / 404 |

Walidacje: `length_real > 0`, `scale > 0`, `name` niepuste, dystans punktów ≥ 1 px,
dozwolone rozszerzenia z `ALLOWED_EXTS` (.jpg/.jpeg/.png), jednostka ∈ {cm, mm, um}.
Błędy: 400 (walidacja), 403 (path traversal), 404 (delete brakującego).

## 5. Workflow użytkownika (UI)

1. Lewy panel → sekcja **Scale** → **＋ New**.
2. Modal: wgraj zdjęcie linijki (klik lub drag&drop) → podgląd na canvasie.
3. (Opcjonalnie) **Powiększ** widok wzorca przyciskami `−` / `＋` / `Fit` nad
   canvasem — przy dużym zdjęciu i małej skali pozwala precyzyjnie trafić w punkty
   (scroll = panowanie). Współrzędne klików są poprawne przy każdym zoomie.
4. Kliknij **2 punkty** na znanym odcinku (3. klik zaczyna od nowa; „reset points").
5. Wpisz **nazwę**, **długość rzeczywistą** + jednostkę (cm/mm/μm), opcjonalnie
   powiększenie → **Save scale**.
6. Skala staje się aktywna (i zapamiętana). Można przełączać skały w dropdownie,
   usuwać (🗑), tworzyć kolejne.
7. Crop → na każdym wycinku rysowany pasek skali wg aktywnej skali. Bez wybranej
   skali crop działa, ale bez paska (tooltip informuje).

## 8. Uwagi / dług techniczny

- Stare pliki `calibration.json` w katalogach zdjęć (jeśli istnieją) są **ignorowane**
  (model porzucony) — można je ręcznie usunąć.
- Element statusbara w HTML zachował `id="status-calibration"` (zmieniono tylko
  tekst na „Scale: …") — kosmetyka, do ewentualnego przemianowania.
- Zmiany **nie są jeszcze scommitowane** (gałąź `web_service`).
- `context_files/` przegenerowane po zmianach (`python generate_context.py`).
